1.
协议总则
1.1 协议概述
本协议基于TCP或UDP协议（根据具体开发需要进行选择），适用于机器人本体与上位机（外部板卡或系统）通信使用。
﻿
1.2 接入通道
本协议使用时，机器人本体为TCP/UDP服务端，外部板卡或系统为TCP/UDP客户端。协议的UDP服务端地址与端口为10.21.31.103:30000，TCP服务端为10.21.31.103:30001。

如下图所示，本协议主要使用请求/响应机制。上位机可主动向机器人本体发起数据或状态查询请求，机器人本体通过响应回复部分请求。

3.
心跳与连接保活
3.1 心跳机制
●
无论使用UDP或TCP，客户端均应以不低于1Hz的频率发送任意指令作为心跳（建议使用特定的心跳指令
Type=100, Command=100
）；服务端超过 2s未收到客户端任何请求则认为客户端离线，停止向该客户端推送所有主动上报数据。
●
使用
UDP
下发运动控制轴指令或速度指令时，建议发送频率不低于20Hz；服务端检测到客户端断开时会自动停止该客户端的速度指令转发，机器人进入安全状态。
●
建议客户端超过3秒未收到服务端任何响应消息时判定服务端断连。
﻿

4.
通讯错误码机制
basic_server 在收到客户端下发的每一个请求后，都会返回该条消息：
JSON 形式：
12
{
  "PatrolDevice": {
    "Type": XXXX,
    "Command": XX,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "ErrorCode": 0,
      "ErrorMessage": "Success"
    }
  }
}
XML 形式：
11
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
    <Type>XXXX</Type>
    <Command>XX</Command>
    <Time>2023-01-01 00:00:00</Time>
    <Items>
        <ErrorCode>0</ErrorCode>
        <ErrorMessage>Success</ErrorMessage>
    </Items>
</PatrolDevice>
其中，回复的 Type 和 Command 字段值与客户端下发的对应请求消息中的 Type 和 Command 字段值相同。
