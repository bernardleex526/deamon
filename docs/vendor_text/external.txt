对外通信方式
山猫 M20 提供两种对外通信方式：
basic_server 协议
（ 由 basic_server 对外提供的
基于 APDU/ASDU 帧协议 的 UDP/TCP 接口
）和 
ROS2 接口
（基于 DrDDS 中间件的话题/服务）。开发者应根据接入条件、功能需求和技术栈选择合适的方式。

1. 
通信架构概述
机器人系统内部各进程之间通过 DrDDS（基于 FastDDS 的中间件）通信，与 ROS2 foxy 兼容；对外由
basic_server
提供运行在 UDP/TCP基础上的通信协议，统一遵循
APDU/ASDU
结构。

3. basic_server 通信协议简介
basic_server 通信协议基于 APDU/ASDU 帧结构，其服务端运行在 AOS 主机的 basic_server 进程上：
●
UDP 30000端口
：无连接、低延迟，适合高频速度指令（≥20Hz）
●
TCP 30001端口
：长连接、可靠传输，适合任务下发和状态订阅
协议核心要素：
●
每帧 = 帧头（4B）+ 数据长度（2B）+ 消息ID（2B）+ 格式（1B）+ 保留（7B）+ ASDU（N 字节）
●
ASDU 以 
PatrolDevice
 为根对象，包含 
Type
（业务大类）、
Command
（子命令）、
Items
（参数）
●
支持 JSON（推荐）和 XML 两种数据格式
详见
basic_server 通信协议总览
。
开发者可以在内部主机上与 basic_server 通过协议通讯，也可以在外部主机上通过 WiFi AP 或 31 网段的对外以太网网口连接到机器人局域网 31 网段后，与 basic_server 通讯。

版本兼容说明
山猫 M20/M20 Pro 使用的操作系统版本为 Ubuntu 20.04，其上运行的 DDS 为 DrDDS（基于 
FastDDS 封装
），ROS版本均为 ROS2 foxy。
如果想让外部主机和山猫 M20 正常通信，需保证
底层都使用 Fast DDS 作为通信标准
。
但机器人本体主机的 ROS 2 Foxy 版本可能会与外部主机的 ROS 2 版本存在兼容性差异，导致看不到话题或数据解析错误。如必须使用 ROS 程序，需参考以下 ROS 版本兼容关系。
山猫M20/M20 Pro版本
外部主机ROS版本
V1.1.7以前版本
ROS2（Foxy、Humble）
V1.1.7及以后版本
ROS 2（Foxy、Humble、Jazzy）

5. 调用逻辑差异
部分功能在两种通信方式下的调用逻辑存在差异，需要依据各个功能模块的具体说明来开发调用。
