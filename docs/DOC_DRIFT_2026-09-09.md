## 四、对"用 2026-09-06 快照做的技术判断是否仍然成立"的明确结论

**结论：绝大多数成立，但有 2 篇必须更新，其中 1 处存在实质性风险。**

1. **仍然成立（可直接沿用）**：所有 11 项关键事实所在的文档 —— `lidar`、`lidar_external`、`motion_basic`、`motion_ros`、`modes`、`hardware`、`topics`、`protocol`、`dds`、`network`、`time`、`architecture`、`compute`、`estop`、`external` —— 归一化后与线上逐字符一致。**任何基于 09-06 快照对这些文档得出的技术判断（雷达权限与坐标变换、组播转发、Cmd=21/25 模式限制、步态速度范围、500ms 超时、模式值、心跳前置条件、NavCmd 冲突、机身尺寸等）均依然成立。**

2. **必须更新（`updates`）**：线上新增 V1.2.0.1 版本条目（M20 18 条、M20 Pro 31 条）。旧快照的"最新版本是 V1.1.8"这一判断已过时；但 `V1.1.7` / `V1.1.8` 的历史条目内容未被改写，基于它们做的判断不变。

3. **必须更新且存在风险（`development`，软件开发指南）**：
   - 线上新增了 3 个接口小节（`1.2.7 自定义灯语` Type=1101 Command=14、`1.2.10 GPS时间同步设置` Type=1101 Command=16、`1.2.11 外部时间同步` Type=1101 Command=15）与 2 个响应字段（`Confidence`、`Relocation`）。**按旧快照做的接口清单/能力判断会漏掉这 5 项。**
   - **风险点**：休眠状态字段 `Sleep` 的数据类型，旧快照写 `bool`（`已休眠= true 未休眠=false`），线上写 `int`（`已休眠= 1 未休眠= 0`）。**任何按旧快照把 `Sleep` 当布尔量解析的客户端代码，会与线上实际文档不符。** 值得注意的是，快照自己的 `updates` 里 V1.1.7 已写明 `本体监控协议-基础状态上报接口(1002,6)，Sleep参数改为int型` —— 即旧快照内部本就存在"更新说明已改、开发指南未同步"的不一致，线上这次把开发指南补齐了。
   - 同类需同步的还有：休眠设置接口的参数名与取值说明（`休眠模式启停`→`休眠模式设置`、`进入休眠 = true / 唤醒（退出休眠）=false`→`开启休眠 = true / 退出休眠 = false`），以及异常码 0x8507 的名称（`充电停障错误码`→`充电停障错误`，仅名称、码值不变）。

4. **一句话给决策者**：快照的技术判断在"硬件/运动/雷达/网络/话题"这些主力文档上完全有效；若项目涉及休眠状态解析、自定义灯语、GPS/外部时间同步、定位重定位状态，则必须改用线上最新版本，不能继续依赖 2026-09-06 快照。

## 五、方法与局限

### 5.1 归一化规则（用于比对，不修改原始文件）

1. **去 CSS 块**：删除 A 侧以 `:root,` 或 `[data-we-color-scheme=` 起始、以 `--cangjie_*` 与 `}` 结束的样式块（19 篇 A 文件均含）。
2. **去零宽字符**：U+FEFF（BOM）、U+200B–U+200D、U+2060、U+00AD 等。
3. **NFKC 归一**：统一全角/半角标点与数字字母。
4. **去全部空白**：空格 / 换行 / 制表符全部删除，以消除 A/B 两侧换行与空格位置差异（保留"字符→原文下标"映射，用于回引原文）。
5. **主判据**：两侧归一化字符串**完全相等**即判定无内容漂移；不相等则用 `difflib.SequenceMatcher` 做字符级差异，并回引原文中文片段。
6. **分层校验**（`doc_diff_tiers.py`）：L0 原始 → L1 去噪声 → L2 空白折叠 → L3 去全部空白 → L4 去空白+NFKC，用于把"纯格式差异"与"内容差异"分开。
7. **三侧回查**（`check_key_facts.py` / `verify_artifacts.py`）：对争议项与全部关键事实，在 A / B / C（线上原始 HTML，先解 `\uXXXX` → 去标签 → 再解 HTML 实体）三侧计数比对。
8. **快照完整性**：19 个 B 侧 `.txt` 的 SHA256 与 `manifest.json` **全部吻合（0 处不符）**，说明快照文件自 2026-09-06 抓取后未被改动。

### 5.2 无法判定 / 需保留的局限

1. **图表、附件、图片未纳入**：`manifest.json` 自述 `diagrams and attachments not included`，两侧都无法核对图片内容、流程图与附件，本报告结论仅覆盖纯文本正文。
2. **B 侧缺失 5 行 XML 声明**（A=30 / HTML=30 / B=25）：已按"B 侧抽取丢行"归类为伪影，但严格意义上无法 100% 排除"线上在 09-06 之后补加了 5 处相同声明"（可能性低：5 处同时补加且均为同一行、且伴随代码块行号整体 -1）。
3. **B 侧多出 1 处 `显示：`**（A=1 / HTML=1 / B=2）：已按"B 侧抽取重复"归类为伪影。
4. **表格结构无法核对**：两侧均为线性文本，合并单元格、跨行表头、单元格视觉顺序无法验证；本报告只核对单元格文本内容与出现次数。
5. **代码块行号伪影**：两侧都残留代码块左侧行号，`development` 中有 3 个纯数字差异块（行号随之整体平移）。这些已按伪影剔除；若某处行号差异背后还伴随真实内容增删，已由相邻的非数字差异块覆盖并逐条列出。
6. **抽取保真度的边界**：本报告的"一致"是"A 侧与 B 侧抽取结果一致"的强证据，不等于"抽取结果 100% 等于页面渲染结果"。对 11 项关键事实与全部争议项，已额外用线上原始 HTML 做了第三侧确认（全部命中），置信度较高。
7. **`更新日期` 字段**：两侧该字段均为空值（`更新日期：` 后无内容），故无法用日期交叉验证版本，本报告以 `版本号` 字段与新增小节为准。
